사용자가 제공한 HTML의 스타일을 `public/editions/*.html`에 보존하고 공통 렌더러 `news.js`에서 실제 게시 기사를 표시한다. 원본 HTML에 포함된 데모 기사와 가상 삽화는 공개 목록에 넣지 않는다. 기존 `/`와 `/poc`, `/capture`는 유지한다.

## 게시 동작

로컬 관리 화면에서 저장된 초안을 검토하고 Publish를 누르면 기존 Instagram 게시 절차를 실행한다. Instagram 게시 성공(`published`) 또는 게시 결과 미확정(`unknown`)인 기사를 10개 사이트가 함께 읽는다. 기존에 게시 완료된 기사도 표시된다. 초안·실패·생성 중·게시 중인 건은 제외된다. 미확정 기사는 게시 시각이 없으면 관측 시각을 사용한다. Instagram 재게시나 기존 게시 상태 변경은 하지 않는다. Instagram 연결 없이 웹에만 게시하는 별도 동작은 추가하지 않았다.

사이트는 같은 사진과 검토한 게시문을 각 시안으로 보여 준다. 카드뉴스는 대표 이미지와 상세 페이지의 나머지 3장으로 표시한다. 사이트별로 문구를 다시 생성하지 않는다. `/api/news/events`의 SSE 연결로 게시 완료를 감지하면 즉시 최신 기사와 헤드라인을 갱신한다. 공유 저장소를 감시하므로 개발 서버에서 게시해도 공개 서버에 전달된다. 재연결 시에도 목록을 갱신하고, 연결 장애에 대비해 10초 주기 확인을 유지한다. 기사 상세 링크와 읽던 기사는 새 기사가 추가되어도 유지된다.

`GET /api/news`는 공개용 제목·게시문·이미지 경로·게시 시각만 반환한다. 원본 관측 사진·센서값·음성·녹취·프롬프트·Instagram 계정 정보는 반환하지 않는다. `GET /api/news/:id/images/:index`는 게시 완료된 기사에 연결된 저장 이미지만 제공한다. Instagram용 한 시간짜리 이미지 주소와 별개이므로 웹 이미지가 만료되지 않는다. 사용자가 직접 지정한 외부 이미지 URL의 수명은 외부 서비스에 따른다.

게시 JSON이나 저장 이미지를 삭제하면 공개 기사 또는 이미지도 사라진다. 기존 게시 상태를 읽으므로 별도 복사·동기화 큐가 없다.

## 적용 및 검증

`npm test`, `npm run build` 후 실행 중인 공개 API와 Vite preview를 재시작해야 새 API와 경로가 적용된다. 기존 README의 LaunchAgent 종료·시작 절차를 따른다. DNS 변경이나 Instagram 시험 게시 없이 로컬 검증할 수 있다.

검증: 공개 응답의 비공개 필드 제외, 초안·실패 기사의 접근 차단, 미확정 기사의 목록·이미지·실시간 갱신, 4장 이미지 제공, 입력 텍스트 이스케이프, 빈 목록·단일 기사·다수 기사, 상세 링크 유지, 10개 경로 및 마지막 슬래시의 HTTP 응답.
